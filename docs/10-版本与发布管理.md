# 10 版本与发布管理

> 版本：v0.1.0 制度文件　｜　适用：整个仓库（数据、应用、文档、扫描器）
> 核心原则：**旧版本永不被修改**。升级 = 新建版本目录 + 新 git tag，而不是覆盖旧文件。

---

## 1. 为什么需要版本隔离

这个项目同时存在四种"版本"：

| 版本 | 载体 | 变化频率 | 隔离方式 |
|---|---|---|---|
| 应用版本 | `app/` 源码、`releases/vX.Y.Z/dist/` | 每 1–2 周 | 冻结目录 + git tag |
| 数据版本 | `data/*.json` 内的 `meta.data_version` | 每周 | 独立版本号 + CHANGELOG |
| 扫描器版本 | `scanner/` 代码 | 每月 | 随应用版本冻结 |
| 文档版本 | `docs/*.md` | 每次发布 | 发布时快照到 `releases/vX.Y.Z/docs-snapshot/` |

如果不隔离：旧版本页面会被新数据覆盖、无法回滚、无法复现"当时为什么这么评分"、给合作者/未来的自己看的历史全部失效。

---

## 2. 版本号规范（语义化）

`MAJOR.MINOR.PATCH`，前缀 `v`：

| 变化 | 版本位 | 示例 |
|---|---|---|
| 破坏性结构变更（数据契约字段/评分公式变、路由大改） | MAJOR | v1.0.0 |
| 新功能、新页面、新数据源、机会库大幅扩充 | MINOR | v0.2.0 |
| 修 bug、文案、样式、单条数据修正 | PATCH | v0.1.1 |

**规则**

- 应用版本与数据版本**独立**：应用可 v0.2.0 而数据仍 data-v0.1.3；发布清单里两者都记录。
- 版本号只增不复用；打错的 tag 不允许删除/重打（可发 PATCH 修正）。
- `VERSION` 文件保存当前应用版本；`data/taxonomy.json.meta.data_version` 保存数据版本。
- 版本目录名带 `v`：`releases/v0.1.0/`；git tag 同名 `v0.1.0`（附注 tag）。

---

## 3. 目录约定（不可协商）

```
releases/
└── v0.1.0/                     ← 冻结后【只读】，任何情况下不再修改
    ├── dist/                   ← 前端构建产物（双击 index.html 可用）
    ├── DEV.md                  ← 本版本开发文档（架构/文件/命令/测试/已知问题/升级说明）
    ├── OPS.md                  ← 本版本运营文档（数据源状态/日常 SOP/KPI/事故/下步动作）
    ├── MANIFEST.json           ← 版本元数据 + 文件清单 + sha256 + git commit
    ├── CHANGELOG.md            ← 本版本变更明细（相对上一版本）
    └── docs-snapshot/          ← 发布时全部 docs 的快照（12 份）
```

**允许的操作**

- 新增 `releases/v0.2.0/`；更新根目录 `VERSION`；在 `README.md` 增加"当前版本/历史版本"。
- 在 `docs/` 里写*新版本*的文档——但不得改动 `releases/` 内的快照。

**禁止的操作**

- ❌ 修改任何 `releases/vX.Y.Z/` 内的文件（含 dist、文档、清单）。
- ❌ 用同一个版本号重新发布（"覆盖 v0.1.0"）。
- ❌ 删除旧 release 目录或旧 git tag。
- ❌ 在没有 DEV.md / OPS.md 的情况下发布。

## 4. 发布流程（12 步，必须全过）

### 4.1 发布前检查（Gate）

| # | 检查项 | 命令 / 人 | 通过标准 |
|---|---|---|---|
| 1 | 数据流水线 | `python scanner/pipeline.py --all` | 退出码 0 |
| 2 | 数据校验 | `python scanner/validate.py` | V01–V15 全 PASS |
| 3 | 前端类型 | `cd app; pnpm build` | tsc 0 error |
| 4 | 前端产物 | 检查 `app/dist/index.html` | 存在、可打开 |
| 5 | 页面自查 | `file://` 打开 8 个路由 | 无白屏、无控制台报错 |
| 6 | 视觉抽查 | Chrome 截图至少 4 页（指挥台/榜单/详情/扫描室） | 无溢出/错位/空图表 |
| 7 | 红队问题 | `qa/report.md` | 无未关闭的 P0；P1 有明确处理结论 |
| 8 | 文档完整 | `docs/00`–`docs/12` | 12 份齐全且 README 链接可达 |
| 9 | 版本说明 | 准备 DEV.md / OPS.md / CHANGELOG.md 草稿 | 内容真实、不空泛 |
| 10 | 徽章与免责 | 详情页/关于页 | 免责声明、`verified:false` 提示可见 |
| 11 | 清理 | 无临时文件、无 API Key、`git status` 干净 | — |
| 12 | 版本目录 | `releases/vX.Y.Z` 不存在 | — |

### 4.2 执行发布

```powershell
cd E:\全球商机扫描器
powershell -ExecutionPolicy Bypass -File scripts/release.ps1 -Version v0.1.0
```

脚本行为（幂等、失败即停）：

1. 校验版本号格式与目录是否已存在；
2. 跑 `python scanner/pipeline.py --all` + `validate.py`；
3. 跑 `cd app; pnpm install --frozen-lockfile; pnpm build`；
4. 创建 `releases/vX.Y.Z/`，复制 `app/dist` → `dist/`；
5. 复制 `docs/*.md` → `docs-snapshot/`；
6. 要求/生成 `DEV.md`、`OPS.md`、`CHANGELOG.md`（缺失时从模板生成并提示补写）；
7. 生成 `MANIFEST.json`（版本、数据版本、git commit、构建时间、文件 sha256、校验结果）；
8. `git add -A && git commit -m "release: vX.Y.Z" && git tag -a vX.Y.Z -m "…"`；
9. 输出摘要：版本、大小、文件数、打开路径、回滚方法。

### 4.3 发布后

- 更新根 `README.md` 的"当前版本"与"版本历史"；
- 把本次发现的问题写进下一版 backlog（`docs/00` 路线图）；
- 打开发布目录，用 `file://` 再验证一次（防止构建产物路径问题）；
- 通知（如果有多人协作）：版本号、变更摘要、升级注意事项。

## 5. 回滚

**场景**：新版本页面打不开 / 数据校验失败 / 评分明显错误。

**方法 A（最快）**：直接打开旧版本 `releases/vPREV/dist/index.html` 继续用，不动任何文件。
**方法 B（回到代码）**：

```powershell
git switch main
git revert <bad-commit>        # 生成反向提交，保留历史
# 或：git checkout <last-good-tag> -- .   （谨慎，仅临时）
git tag -a vX.Y.Z-hotfix -m "rollback"   # 记录状态，不删旧 tag
```

**禁止**：`git reset --hard` 到旧 tag 后强推覆盖历史（单人本地可接受但会丢失这次发布的记录，默认不做）。

---

## 6. 热修复（PATCH）流程

1. 从当前 `main` 拉出最小修复（不改结构、不改契约）；
2. 数据修正 → 升 `data_version` 的 PATCH 位并写 `data/CHANGELOG.md`；
3. 重跑 pipeline + validate + build；
4. 发布 `vX.Y.(Z+1)`（新目录，不覆盖旧目录）；
5. 在 `DEV.md` 的"已知问题"里记录触发原因与修复方式。

---

## 7. 数据版本迁移规则

| 变更 | 数据版本 | 必做 |
|---|---|---|
| 新增/修正机会、修正分值 | +PATCH | 更新 CHANGELOG、重跑 pipeline |
| 新增枚举项/字段（向后兼容） | +MINOR | 更新 docs/12、通知前端、前端兼容旧字段 |
| 删除/重命名字段、改公式、改权重 | +MAJOR | 更新 docs/12、前端与扫描器同步、写迁移说明 |
| 旧版本兼容 | — | 前端必须能容忍缺失字段；不允许因数据升级导致旧 release 打不开（release 自带打包数据，天然隔离） |


## 13. 线上发布（GitHub Pages，v0.2.0 起）

- 仓库：https://github.com/charline88888-ux/opportunity-radar（public）
- 线上版：https://charline88888-ux.github.io/opportunity-radar/
- Pages 配置：`gh-pages` 分支根目录（`.nojekyll`，无需 Jekyll/构建）
- 站点结构：`/` = 最新冻结版；`/v0.1.0/`、`/v0.2.0/`… = 历史版本归档；`versions.json` = 版本索引；`404.html` = 回退到最新版
- 发布命令：
  ```powershell
  $env:GITHUB_TOKEN = "ghp_xxx"   # 需要 repo 权限；不要写入仓库
  powershell -ExecutionPolicy Bypass -File scripts/deploy-pages.ps1 -Version v0.2.0
  ```
- 发布顺序：**先** `scripts/release.ps1` 冻结本地版本 → **再** `deploy-pages.ps1` 上线；线上只发布已冻结产物，不允许从工作区直接部署。
- 验证：`deploy-pages.ps1` 会自动轮询 URL；发布后核对 About 页版本号、KPI 与 `releases/vX.Y.Z/MANIFEST.json` 一致。
- 回滚：线上回滚 = 把 `gh-pages` 指向旧版站点提交，或直接分享旧版归档路径 `/vX.Y.Z/`（本地冻结版仍可用）。
- Token 管理：只在当前 shell 环境变量/参数中传递，禁止提交；泄露后立即在 GitHub → Settings → Developer settings 撤销。
