# 07 技术架构与扫描流水线

> 版本：v0.1.0　｜　目标：一个人、一台 Windows 电脑、零服务器成本，跑通「采集 → 归一 → 去重 → 富化 → 评分 → 排榜 → 发布」全链路。
> 本文与 [`docs/12-数据契约与字段字典.md`](12-数据契约与字段字典.md) 配套：契约定义数据长什么样，本文定义数据怎么流动、代码怎么组织、以后怎么扩展。

---

## 1. 设计目标与约束

| 约束 | 决策 |
|---|---|
| 本地优先、隐私第一 | 数据与页面全部落盘本机；无账号、无云端、无遥测 |
| 零服务器成本 | 静态前端 + 本地 Python 批处理；不部署后端 |
| 离线可用 | 前端构建期打包数据，无 CDN/外网请求；`file://` 可打开 |
| 一个人能维护 | Python 标准库实现核心流水线；依赖少、命令少 |
| 数据可回溯 | 每条机会保留证据 URL、抓取时间、来源层级；可重放 |
| 可替换 | 适配器/评分器/前端各自独立，换实现不改契约 |
| 合规 | 只采公开信息；限速；`compliance:red` 源只人工浏览；不绕过登录/付费墙 |

**技术选型**

| 层 | v0.1.0 选型 | 理由 |
|---|---|---|
| 数据存储 | JSON 文件（`data/*.json`） | 可读、可 diff、可版本化；个人量级（<1 万条）足够 |
| 扫描器 | Python 3.11 标准库 | 零安装；`json/datetime/hashlib/urllib/re/sqlite3` 够用 |
| 前端 | Vite + React + TS + Tailwind + ECharts | 构建产物可离线；图表专业；类型安全 |
| 调度 | 手动命令（v0.1）→ Windows 任务计划程序（v0.2） | 先确保正确，再自动化 |
| 增强 | LLM 可选（v0.2 起） | 翻译/摘要/七问初稿，人工复核后入库 |
| 版本管理 | git + `releases/vX.Y.Z/` 冻结目录 | 升级不污染旧版本 |

**数据流原则**

1. **单一写入口**：`rankings.json`、`stats.json` 只能由扫描器生成；`opportunities.json` 只能由数据流程维护；前端只读。
2. **契约先行**：任何字段变化先改 `docs/12`，再改代码，再重建；不允许代码私改结构。
3. **可重放**：同一份 `opportunities.json` + 同一版扫描器，输出必须完全一致（确定性，不依赖当前时间以外的随机因素）。
4. **失败阻断**：校验不过不出榜、不发布。

## 4. 模块设计

### 4.1 采集适配器 `scanner/adapters/`

统一接口（v0.1.0 先用 fixtures 打通结构，v0.2 接真实网络）：

```python
class Adapter:
    id: str                 # "reddit"
    compliance: str         # green/yellow/red
    def fetch(self, query: dict) -> list[dict]:
        """返回 RawSignal 列表；必须自带来源 URL、抓取时间、原文语言。"""
```

已规划适配器（v0.1 只实现离线 fixtures 版本）：

| 适配器 | 源 | 信号类型 | 合规 |
|---|---|---|---|
| `rss_adapter` | 行业媒体/官方博客/论坛 RSS | 趋势、政策、案例 | 绿 |
| `reddit_adapter` | subreddit 热帖与评论 | 抱怨、愿望、比较 | 黄（API 收费/限速） |
| `trends_adapter` | Google Trends / 平台热搜导出 CSV | 搜索趋势 | 黄（非官方接口） |
| `marketplace_adapter` | 电商评论、Bestsellers、Etsy 热销 | 价格、差评、爆品 | 黄 |
| `policy_adapter` | EUR-Lex / Federal Register / 政府公报 RSS | 监管、补贴、招标 | 绿 |
| `manual_import` | 人工粘贴链接 + 笔记 | 任意 | 绿 |

**RawSignal 结构（归一化输入）**：

```json
{
  "source_id": "reddit",
  "url": "https://…",
  "title": "…",
  "text": "…",
  "lang": "en",
  "published_at": "2026-10-20",
  "fetched_at": "2026-10-22T06:00:00+08:00",
  "signal_type": "complaint",
  "region_hint": "north-america",
  "tier": "primary"
}
```

### 4.2 归一化 `normalize.py`

- 清洗 HTML、去 emoji 噪声（保留语义）、统一日期 → ISO；
- 语言识别（v0.1 用字符集 + 停用词启发式；v0.2 可接 `langdetect`）；
- 候选映射：关键词/别名 → `industry_id`、`gap_type_ids`、`region_ids`（词典在 `scanner/core/keywords.json`，与 taxonomy 对齐）；
- 证据分层：官方/平台/用户原声 = `primary`；媒体报道/报告 = `secondary`；品牌稿/软文特征 = `marketing`；
- 输出符合契约 `RawSignal`，供去重与机会生成使用。

### 4.3 去重 `dedupe.py`

三层策略（成本从低到高）：

1. **URL 规范化**：去 utm/tracking 参数、去 fragment、统一大小写 host、去尾斜杠；
2. **标题指纹**：标题去标点/停用词后 SimHash（64 位），汉明距离 ≤ 3 判重；同 URL 前缀 + 相似标题合并；
3. **事件聚类**（v0.2）：同实体 + 同事件（时间窗 7 天）合并，保留最早 `first_seen` 与最新 `last_activity`；
4. 合并规则：证据取并集、来源 tier 取最高、`signal_strength` 取最大值、冲突字段保留人工裁决记录。

### 4.4 机会生成 `opportunity.py`

v0.1.0：**人工撰写 + 脚本体检**。理由：机会质量取决于判断，自动化初稿会稀释可信度。脚本只做：

- 必填字段体检（七问、证据、ROI、风险、动作）；
- 派生字段计算：`evidence_count`、`first_seen`、`last_activity`、`activity_dates` 排序、`momentum`、`rank_score`；
- 一致性检查（行业/信息差/区域 id 存在、日期合法）。

v0.2：LLM 初稿流程（人工必须复核）：

```
signals[] → 聚类主题 → prompt（含 taxonomy 枚举 + 七问模板 + 证据原文）
        → JSON（严格 schema）→ 规则校验 → 人工 10 分钟复核 → 入库
```
Prompt 要求：只能引用给定证据、不知道就写"未知"、不得编造数字/URL、输出中文、七问必须具体。生成结果落 `scanner/outbox/*.json`，复核后才进 `data/opportunities.json`。

### 4.5 评分 `score.py`

严格实现契约 §4.5：

```python
WEIGHTS = {"signal":.15,"gap":.15,"feasibility":.15,"economics":.15,"timing":.10,
           "competition":.08,"risk":.07,"fit":.05,"evidence":.05,"leverage":.05}
total = round(sum(dim[k]*WEIGHTS[k] for k in WEIGHTS)*10, 1)
rank_score = round(min(100, total*(1+0.12*(momentum-1))), 1)
GRADE = lambda t: "S" if t>=85 else "A" if t>=75 else "B" if t>=65 else "C" if t>=55 else "D"
```

规则：

- 维度分数缺失 → 校验失败（不允许默认 0 分混过）；
- `momentum` 缺失/异常 → 置 1.0 并在运行日志告警；
- 重算值与文件值不一致 → 以计算值为准写回，并输出告警（数据质量问题）；
- 权重来自 `taxonomy.json.score_dimensions`，代码不得硬编码第二份（单一来源）。

### 4.6 排榜 `rank.py`

- 按契约 §5：窗口归属（day/week/month/year）+ 排序（rank_score, momentum, evidence_count, last_activity）+ rank 编号 + delta（v0.1 允许 null/new）；
- 窗口 key 计算：`day = as_of`；`week = ISO 年-周`（Python `isocalendar()`）；`month = YYYY-MM`；`year = YYYY`；
- 输出确定性：同分按 opp_id 升序兜底，保证重复运行结果一致；
- 历史快照（v0.2）：每次运行把 rankings 存 `data/history/rankings-YYYYMMDD.json`，用于计算真实 delta 与趋势。

### 4.7 统计 `stats.py`

生成 `data/stats.json`：KPI、按行业/信息差/区域/需求分布、评分直方图、14 天趋势、开放窗口价值。必须与机会库实际聚合一致（validate V14）。

### 4.8 校验 `validate.py`

实现契约 §9 的 V01–V15，输出：

```
[PASS] V01 枚举引用完整
[FAIL] V05 opp-xxx total=78.6 但重算=80.1
...
结果：14 通过 / 1 失败 → exit 1
```

CI 化：发布前必须 `python scanner/pipeline.py --all && python scanner/validate.py` 全绿。

### 4.9 CLI `pipeline.py`

```powershell
python scanner/pipeline.py --all        # 归一→去重→派生字段→评分→排榜→统计→校验
python scanner/pipeline.py --rank       # 只重算榜单与统计
python scanner/pipeline.py --validate   # 只校验
python scanner/pipeline.py --ingest scanner/fixtures/raw_signals.json  # 跑适配器样本
```

退出码：0 成功；1 校验失败；2 输入缺失/结构错误。日志写 `scanner/logs/run-YYYYMMDD-HHmmss.log`（含耗时、条数、告警）。

## 5. 存储设计

### 5.1 v0.1.0：JSON 文件

优点：可读、可 review、可 git diff、无依赖。限制：>1 万条后排序/查询变慢、并发写不安全（单人使用可接受）。

写入策略：**原子写**（先写 `.tmp` 再 `os.replace`），避免中途崩溃损坏文件；每次运行前自动备份到 `data/.backup/`（保留最近 5 份，gitignore）。

### 5.2 v0.2：SQLite（迁移预案）

```sql
CREATE TABLE sources(id TEXT PRIMARY KEY, name TEXT, category TEXT, access TEXT,
  compliance TEXT, value_score REAL, last_checked TEXT, health TEXT);
CREATE TABLE raw_signals(id INTEGER PRIMARY KEY, source_id TEXT, url TEXT UNIQUE,
  title TEXT, text TEXT, lang TEXT, published_at TEXT, fetched_at TEXT,
  signal_type TEXT, region_hint TEXT, tier TEXT, hash TEXT);
CREATE TABLE opportunities(id TEXT PRIMARY KEY, slug TEXT, title TEXT, one_liner TEXT,
  industry_id TEXT, gap_type_ids TEXT, region_ids TEXT, origin_country TEXT,
  target_countries TEXT, human_need_ids TEXT, neuro_drivers TEXT, emotion_tags TEXT,
  source_langs TEXT, signal_json TEXT, seven_questions_json TEXT, roi_json TEXT,
  scores_json TEXT, window_json TEXT, risks_json TEXT, first_steps_json TEXT,
  kill_criteria_json TEXT, compliance_notes TEXT, activity_dates TEXT,
  first_seen TEXT, last_activity TEXT, momentum REAL, rank_score REAL,
  tags TEXT, verified INTEGER, created_at TEXT, updated_at TEXT);
CREATE TABLE evidence(id INTEGER PRIMARY KEY, opp_id TEXT, title TEXT, publisher TEXT,
  url TEXT, date TEXT, quote TEXT, lang TEXT, tier TEXT, verified INTEGER,
  first_seen TEXT);
CREATE TABLE rankings_history(as_of TEXT, window TEXT, window_key TEXT,
  opp_id TEXT, rank INTEGER, rank_score REAL, PRIMARY KEY(as_of, window, opp_id));
CREATE TABLE experiments(id INTEGER PRIMARY KEY, opp_id TEXT, started_at TEXT,
  status TEXT, budget_cny REAL, hours REAL, result TEXT, ended_at TEXT);
CREATE TABLE source_health(source_id TEXT, checked_at TEXT, ok INTEGER,
  latency_ms INTEGER, note TEXT);
```

迁移路径：`scanner/migrate_to_sqlite.py` 读 JSON → 写 SQLite → 前端仍读导出 JSON（构建期导出），保证前端零改动。

## 6. 真实采集策略（v0.2 设计，v0.1 不联网执行）

| 主题 | 策略 |
|---|---|
| 限速 | 每域名 ≤ 1 req/2s，单次运行 ≤ 200 请求；遵守 `robots.txt` 与 ToS；带真实 UA 与联系邮箱 |
| 缓存 | `scanner/cache/<source>/<hash>.html`，7 天内不重复请求；ETag/Last-Modified |
| 增量 | 按 `published_at` 水位线（watermark）与 RSS 条目 id 去重 |
| 失败重试 | 指数退避 3 次；连续 3 次失败标记源为 `unhealthy` 并降频 |
| 合规 | `compliance:red` 源只允许人工浏览复制；不绕过登录、验证码、付费墙；不采集个人信息 |
| 成本 | 全免费源优先；付费 API 按月预算上限（默认 0 元）；LLM 调用只在富化阶段且可缓存 |

**源健康度监控**：每次运行记录每个源的请求数/成功率/新增信号数；`/sources` 页面展示健康度；连续失败 3 次自动在数据源文档标红并建议替代源。

## 7. LLM 增强（可选层，v0.2 起）

| 用途 | 输入 | 输出 | 人工复核 |
|---|---|---|---|
| 翻译/术语解释 | 原文 + 目标语言 | 译文 + 术语表 | 抽样 20% |
| 信号归因 | 一段文本 | 需求/情绪/信息差候选 id、理由 | 全部 |
| 七问初稿 | 证据集合 + 模板 | JSON（严格 schema） | 全部 |
| 去重聚类 | 标题列表 | 聚类结果 | 抽检 |
| 报告摘要 | stats + 榜单 | 日报/周报草案 | 编辑改写 |

约束：模型只能使用提供的证据；输出必须通过 JSON schema 校验；禁止模型直接写 `data/opportunities.json`（只写 outbox）；每次调用记录 prompt 版本、模型、token 成本；提示词与解析代码版本化。

**成本估算（v0.2 参考）**：40 条机会 × 每条 2 次富化 ≈ 80 次调用；单次 ≤ 6k tokens，月成本 < ¥50（视模型而定）；缓存命中后接近 0。

## 8. 前端架构

- **构建**：Vite 构建时 `scripts/sync-data.mjs` 把 `../data/*.json` 复制到 `app/src/data/`，前端 `import` 打包进 JS，无 fetch、无 CDN → `file://` 直接可用。
- **路由**：HashRouter（`#/rankings`），刷新不 404。
- **状态**：URL query（筛选/窗口）+ React state + localStorage（个人画像、实验清单、checklist 勾选）。
- **图表**：ECharts 按需引入（`echarts/core` + Radar/Heatmap/Sankey/Treemap/Bar/Line/Scatter/Graph/Gauge），统一深色主题；图表容器必须有固定高度与空态。
- **性能**：页面级代码分割（React.lazy）；首屏只加载指挥台所需图表；大表分页/虚拟滚动（v0.2）。
- **可访问性**：语义标签、键盘操作、对比度达标、`prefers-reduced-motion` 关闭动画。
- **构建校验**：`tsc --noEmit` + `vite build` 必须 0 error；产物 `dist/` 双击可开。

## 10. 可观测性

## 11. 安全与隐私

- 所有数据落本机；无账号、无上传、无第三方统计脚本。
- API Key（v0.2 如需）放本机 `.env`，`.gitignore` 排除；仓库中永不出现密钥。
- 研究/数据中只保留公开信息；不收录个人隐私、不收录需要登录才能看的内容。
- 外链一律 `noopener noreferrer`；前端不执行外部脚本。

## 13. 已知局限（v0.1.0 诚实清单）

1. 数据以「人工研究 + 离线样本」为主，**不是实时全自动抓取**；日均新增依赖人工投入 30–60 分钟。
2. `momentum` 基于 `activity_dates` 估算，尚无真实历史快照，榜单 delta 多为 `new`。
3. 证据核验为抽样级别，`verified:false` 条目必须使用前复核。
4. 前端个人画像与实验看板为 localStorage 轻量版，不跨设备同步。
5. 文化维度（Hofstede）为静态内置数据，非实时更新。
6. 语种覆盖以中英为主，其他语种依赖人工/机器翻译，术语（宗教/法律）需专家复核。
