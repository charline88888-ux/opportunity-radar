# 11 补充清单 · 40 个容易踩的坑与放大器

> 你说"还有我没想到的你帮我补充"。这一份就是补充：40 条在「个人全球商机扫描」这件事上，**不做会死、做了会赢**的东西。
> 每条给出：问题 → 为什么重要 → 怎么做（v0.1.0 已落地 / 下版本落地）。

---

## A. 需求与信号（1–8）

**1. 信息差有半衰期，机会会过期。**
问题：只排名不分新旧，会把三年前的机会当新机会。
为什么重要：信息差的价值随时间衰减，晚 6 个月可能从"套利"变"内卷"。
怎么做：每个信息差类型设默认半衰期（语言 24 个月、平台 6 个月、文化 36 个月…），机会带 `window.months_left` 与 `status`，前端显示"窗口剩余"，过期自动下榜进档案。（v0.1.0 已落地字段与展示）

**2. 假信号比没信号更危险。**
问题：营销稿、刷单好评、幸存者偏差、爆款回撤，都会伪装成"需求爆发"。
为什么重要：照着假信号执行 = 直接亏钱。
怎么做：证据分三层（一手/二手/营销稿），营销稿不计入证据分；要求跨主体三角验证；`verified:false` 显式标注；单条机会 ≥2 个独立来源才算 A 级。（已落地）

**3. 抱怨不等于需求，愿望不等于付费。**
问题：用户骂得凶，不代表愿意掏钱。
为什么重要：最贵的错误是做了一个"大家都说好但不买"的产品。
怎么做：抱怨→机会必须过五问：频率×痛苦强度×现有方案糟糕度×**支付意愿证据**×可触达性；支付意愿证据包括：已有付费替代品、众筹金额、二手溢价、评论里"我愿意花 X 买"。（docs/03 方法论 + 评分 economics 维度）

**4. 只扫英语世界 = 只看到 20% 的信息差。**
问题：默认刷 Reddit/Product Hunt，会漏掉中东、日本、韩国、拉美、非洲。
为什么重要：非英语市场的信息差更大、竞争更小，是个人最大优势区。
怎么做：数据源矩阵强制覆盖 11 个区域、非英语源 ≥40%；每周至少 1 次"非英语扫描日"；翻译/术语用人工复核。（已落地矩阵与剧本，运营手册有排期）

**5. 别只看"新"，还要看"消失"。**
问题：只记录新增机会，不记录下架/证伪的机会。
为什么重要：消失的机会是最好的老师（判断哪些是伪需求）。
怎么做：机会状态 `open/peak/closing/closed`，关闭要写原因；年鉴复盘"消失的机会"。（已落地字段；年鉴模板在 docs/06）

**6. 情绪要分"可商业化的情绪"和"只能共情的情绪"。**
问题：把社会议题当商机，容易踩雷或做不出付费。
为什么重要：情绪价值必须能对应到"谁愿意为缓解/放大这个情绪付钱"。
怎么做：情绪→商业输出反推表（≥30 条），标出"高付费意愿/低付费意愿/不可商业化"。（docs/03）

**7. 平台热搜是滞后指标，评论区才是先行指标。**
问题：等上热搜时，红利期通常只剩 1–2 个月。
为什么重要：个人抢的就是"别人还没反应过来"的窗口。
怎么做：扫描优先级：评论区/差评/求推荐帖 > 新兴榜单 > 热搜；每周记录"信号首现日"，回看提前量。（docs/03 剧本 + activity_dates）

**8. 不要用单一平台的数据做因果判断。**
问题：Etsy 卖得好 ≠ 独立站能卖；TikTok 爆 ≠ 亚马逊能爆。
为什么重要：渠道属性决定价格带与转化逻辑。
怎么做：任何机会至少验证 2 个渠道的价格与竞争；评分里"渠道/平台依赖"作为风险项。（评分 risk + docs/02）

## B. 评分与决策（9–16）

**9. 评分公式必须可解释、可校准、可被推翻。**
问题：黑箱打分 → 无法判断错在哪 → 无法进步。
为什么重要：这是长期复利的核心资产。
怎么做：10 维公开权重 + 锚点 + 证据链接；每季度用已执行机会回测（预测等级 vs 实际结果），写校准报告。（docs/04）

**10. 分数不等于适合你。**
问题：同一机会对 A 是 S 级，对 B 是 D 级。
为什么重要：个人资源/技能/语言/身份差异巨大。
怎么做：个人画像（资金/时间/技能/语言/供应链/风险偏好）+ 机会适配度维度；推荐分 = 机会分 × 适配度。（v0.1 前端已做轻量画像；v0.2 持久化）

**11. 榜单会被"看起来厉害"的东西带偏。**
问题：高热度、高客单、高科技的视觉冲击会压过低资本、慢热、高确定性机会。
为什么重要：个人更需要"能启动"而不是"听起来牛"。
怎么做：固定"反直觉位" + "低资本位"；算法权重里 feasibility 与 low-capital 标签加权；编辑器可置顶但必须写理由。（docs/06）

**12. 没有"证伪条件"的机会不是机会，是信仰。**
问题：很多人只写"为什么能成"，不写"什么情况下放弃"。
为什么重要：止损能力决定你能试多少次。
怎么做：每条机会强制 `kill_criteria`（2–4 条可观测条件）+ 7 天验证动作 + 预算上限。（已落地）

**13. 一次只追一个机会，不是效率低，是唯一可行解。**
问题：榜单越做越厚，人越看越焦虑，一个都不做。
为什么重要：个人产能上限是每周 1 个实验。
怎么做：每周最多 1 个"进行中实验"，其余进观察池；指挥台显示"进行中 N/1"；实验看板记录结论。（docs/08 + 前端实验清单）

**14. 决策要留痕：当时为什么选它。**
问题：三个月后忘了为什么做、为什么放弃。
为什么重要：复盘和校准的原料。
怎么做：每条机会可复制"决策卡"（选择理由/预算/止损线/预期）；实验记录状态与结论。（v0.1 导出 Markdown；v0.2 看板）

**15. 警惕"信息差陷阱"：知道的人越少 ≠ 越赚钱。**
问题：有些冷门信息差的根本原因是"没有需求/不可交付/违法"。
为什么重要：冷门可能是别人试过的坟场。
怎么做：冷门机会必须额外验证"为什么别人没做"（供给障碍/合规/需求不存在/渠道问题），并在风险里写清楚。（docs/04 红榜/黑榜）

**16. 用"组合"而不是"重注"管理不确定性。**
问题：all-in 一个机会，失败就归零。
为什么重要：个人抗风险能力低。
怎么做：把机会分为 3 个篮子：低成本快验证（≤500 元）/ 中等投入（≤1 万）/ 长期资产（内容/品牌）；用凯利思维控制单次投入上限。（docs/08 组合管理）

## C. 执行与转化（17–24）

**17. 扫描器最大的敌人是"收藏夹吃灰"。**
问题：看得越多，做得越少，产生"学习幻觉"。
为什么重要：不执行 = 零价值，还会消耗信心。
怎么做：核心指标改为"每周完成验证数"；榜单 CTA 是"开始 7 天验证"；每周复盘只问三个问题：做了什么/花了多少/结论是什么。（已落地产品指标与 SOP）

**18. 7 天验证必须有预算上限和"最小可售卖物"。**
问题：验证动作写成"调研市场"这种无法结束的任务。
为什么重要：没有边界的验证会无限拖延。
怎么做：每个实验：预算 ≤ 500 元、时间 ≤ 7 天、必须产出"可展示给真实客户的东西"（落地页/样品/报价单/一条内容）；指标提前写死。（已落地 first_steps_7d 模板）

**19. 先找"已经在赚小钱的人"，再倒推需求。**
问题：从零猜需求，命中率极低。
为什么重要：反向验证比正向推理可靠得多。
怎么做：扫描时优先找：Fiverr/Upwork 有订单、Etsy 有销量、独立站有广告、社群有人收费、招标有人中标；把这些作为"需求已存在"的证据。（docs/03 反向验证法）

**20. 交付物决定复购：服务类要模板化，实物类要供应链化。**
问题：第一单靠热情交付，第二单就崩。
为什么重要：个人产能有限，必须靠标准化放大。
怎么做：每条机会写清"交付 SOP 雏形"与"可复制部分"；服务类沉淀话术/模板/清单，实物类锁定 2–3 家供应商与质检标准。（详情页行动区 + docs/01）

**21. 现金流周期比毛利率更致命。**
问题：只看毛利 60%，忽略平台账期、备货压款、退款。
为什么重要：个人现金流断裂 = 项目死亡。
怎么做：ROI 必填"回本周期/现金流特征"；跨境机会额外标"备货资金/账期/退货率"。（ROI 字段 + docs/01）

**22. 内容是最好的低成本流量，但也是最慢的。**
问题：指望投广告启动，个人预算不够；只做内容又太慢。
为什么重要：需要组合拳。
怎么做：流量答案必须写"前 100 个客户从哪来"（具体渠道+内容形式+合作方式），并给一个"7 天可发的 3 条内容"。（七问 traffic + docs/05）

**23. 服务/信息类机会被严重低估。**
问题：大家盯着实物爆品，忽略翻译、合规、代办、咨询、培训、数据服务。
为什么重要：服务类资本门槛低、毛利高、可用 AI 提效，最适合个人。
怎么做：行业板块固定包含合规/教育/文化/专业服务；扫描剧本中有"专业门槛型服务"清单（宗教文本、法律、认证、税务、医疗翻译…）。（taxonomy + docs/03）

**24. 给自己设"不做清单"。**
问题：机会太多，边界不清，容易被灰产/高风险吸引。
为什么重要：避免一次性毁灭性错误。
怎么做：明确不碰：荐股炒币、医疗承诺、侵权盗版、平台违规、宗教冒犯、传销/资金盘、个人信息买卖；写进关于页与评分黑榜。（docs/04 黑榜 + 前端免责）

## D. 商业与产品化（25–31）

**25. 先自用跑通，再谈卖给别人。**
问题：一上来就想做 SaaS 卖订阅，结果自己都没用它赚过钱。
为什么重要：没有实战校准的评分系统没有说服力。
怎么做：阶段一（0–90 天）只服务自己；阶段二用"自己的验证结果"做案例再考虑订阅；产品化前先攒 12 个真实实验记录。（docs/01 四阶段）

**26. 卖"信息"有伦理与法律边界。**
问题：把公开信息打包卖，可能涉及版权/误导/投资建议资质。
为什么重要：这是最容易翻车的地方。
怎么做：只卖"研究过程+方法论+工具"，不承诺收益；不转售受版权保护的原文；不做个性化投资建议；免责声明常驻。（docs/09 合规）

**27. 定价按"节省的时间/避免的亏损"锚定，不按"信息条数"。**
问题：按条数卖会陷入低价内卷。
为什么重要：用户买的是决策质量。
怎么做：订阅权益写：每周 1 个可执行实验、每月 1 份主题报告、评分回测、实验复盘模板；价格锚定"帮你避免一次 5000 元错误"。（docs/01 定价）

**28. 你的护城河是"校准过的判断力"，不是数据。**
问题：数据谁都能抓，AI 也能总结。
为什么重要：差异化在"哪些机会真的让普通人赚到钱"的长期记录。
怎么做：建立"预测→执行→结果"数据库；每次复盘回填；季度校准权重；对外输出校准报告。（docs/04 + docs/08）

**29. 警惕"卖铲子给淘金者"的诱惑。**
问题：发现做商机内容比做商机更赚钱，于是变成卖课号。
为什么重要：短期变现会毁掉长期可信度。
怎么做：规定"自己必须先做/投过至少 1 个实验，才写该主题报告"；收入结构里自营项目占比目标 ≥ 30%。（docs/01 价值观）

**30. 建立 3–5 人红队小组。**
问题：一个人判断容易自嗨。
为什么重要：交叉验证能显著降低误判。
怎么做：每周把 1 个机会卡发给 2–3 个不同背景的朋友，要求只挑毛病；把反对意见写进风险字段。（docs/08 社群）

**31. 把"扫描结果"变成资产，而不是一次性消费品。**
问题：做完榜单就结束，没有复利。
为什么重要：内容/数据/案例都能滚雪球。
怎么做：每条机会的验证过程沉淀为案例；每月输出 1 篇深度；年度做成"机会年鉴"（可付费/可引流）。（docs/06 年鉴 + docs/08 内容化）

## E. 数据与合规（32–36）

**32. 抓取合规是生死线。**
问题：无视 robots.txt/ToS、高频请求、抓个人信息 → 封 IP、律师函。
为什么重要：个人项目经不起法律风险。
怎么做：源分绿/黄/红；限速；不绕过登录/付费墙；不存个人信息；red 源只人工看；记录来源与抓取时间。（docs/02/07/09）

**33. AI 会一本正经地编造来源和数字。**
问题：LLM 生成的"市场数据"看起来专业但可能是假的。
为什么重要：一条假数据会毁掉整个报告可信度。
怎么做：LLM 只做翻译/摘要/初稿；所有数字必须人工核对原始来源；输出 JSON schema 校验；`verified` 标记；不确定就写"未知"。（docs/07 LLM 约束）

**34. 数据要能断点恢复。**
问题：抓一半崩了、文件写坏。
为什么重要：重建成本极高。
怎么做：原子写（tmp+replace）、每次运行前备份、原始信号落盘可重放、watermark 增量。（docs/07）

**35. 汇率、税、平台佣金会吃掉利润。**
问题：ROI 估算只算进货价，忽略隐性成本。
为什么重要：很多"看起来赚钱"的机会实际亏钱。
怎么做：ROI 模板强制列：平台佣金、支付手续费、物流/退货、税费、汇率损耗、广告费；给保守/基准/乐观三档。（docs/05 ROI 模板）

**36. 地缘与政策风险要有仪表盘。**
问题：战争、制裁、关税、平台封国，会让机会一夜归零。
为什么重要：跨境机会的尾部风险极高。
怎么做：机会标注"受影响区域/平台"；每月检查政策与平台公告；高风险区域降低权重或标注"仅观察"。（docs/02/09）

## F. 系统与版本（37–40）

**37. 每次升级必须"可回滚、可对比、不污染"。**
问题：改着改着旧版打不开，也不知道哪版更好。
为什么重要：这是长期迭代的基础设施。
怎么做：`releases/vX.Y.Z/` 冻结 + MANIFEST + 数据版本独立 + git tag；旧版本只读；DEV/OPS 每版必写。（已落地 docs/10 + 发布脚本）

**38. 数据与代码要同版本可复现。**
问题：半年后想复现"当时为什么这么排"，数据已经变了。
为什么更重要：评分系统需要历史回测。
怎么做：每次发布快照数据版本；v0.2 起保存 rankings_history（每日榜单快照），可回放任何一天的榜单。（docs/07）

**39. 备份与迁移计划。**
问题：硬盘坏 = 几年研究归零。
为什么重要：数据资产比代码值钱。
怎么做：仓库本身 + `data/` 定期压缩备份到第二个盘/私有仓库（注意不含敏感信息）；提供导出/导入命令；每季度演练一次恢复。（docs/08）

**40. 不要过度工程：v0.1.0 的目标是"跑通闭环"。**
问题：一上来就微服务、爬虫集群、向量数据库。
为什么重要：个人项目最容易死在"架构很美但没人用"。
怎么做：JSON + 标准库 + 静态前端 → 验证有人（自己）真的每天用 → 再按瓶颈升级（SQLite → 定时任务 → LLM → 多用户）。（docs/07 扩展路线）
